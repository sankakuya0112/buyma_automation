# BUYMA 自動出品システム: 収益性レビュー用 仕様書

**作成日**: 2026-04-23  
**目的**: 本システムで実際に利益が出せるか、第三者 AI にレビューしてもらう
ための仕様・ロジック・実データのまとめ。

---

## 1. ビジネスモデル

### 1.1 概要

- **チャネル**: BUYMA (日本の海外ブランド個人輸入マーケットプレイス)
- **ポジション**: パーソナルショッパー (受注後にショッパーが現地購入→
  国際配送→日本の購入者に発送)
- **仕入元**: baseblu.com (イタリアのマルチブランド EC)
- **扱い商材**: ハイブランド〜ブティック系のアパレル・バッグ・シューズ

### 1.2 収益の仕組み

BUYMA では買い手が注文 → ショッパーが baseblu で買い付け → 自宅受取 →
再梱包 → 国際配送 → 手数料引かれ入金。

1 取引あたりの収益 = 売価 − (仕入原価 + VAT還付 + 関税 + 送料 + 消費税
+ BUYMA手数料 + 決済手数料)

### 1.3 運用形態 (ユーザ確認済)

- **自社発送**: 配送代行は使わない (1 件あたり 30-60 分の労働負荷)
- **返品ポリシー**: ショッパー負担 (国際送料がかかる)
- **最低利益額**: `max(¥5,000, 売価 × 5%)` (自社発送 + 返品リスクを考慮)

## 3. 価格計算ロジック

### 3.1 原価計算 (固定パラメータ)

```
源泉仕入値 (EUR) × 為替 163 JPY/EUR = 源泉JPY
- VAT還付 16.7%                      (EU域外輸出)
+ 国際送料 3,000 JPY/kg × カテゴリ別重量 (バッグ 1.0-1.5kg, 靴 0.9-1.6kg 等)
+ 関税 (カテゴリ別 5-17%)
+ 輸入消費税 10% (仕入値 + 送料 + 関税 に対して)
= 総原価 JPY
```

### 3.2 目標売価 (25% 利益率の逆算)

```
売価 = 原価 × (1 + 25%) / (1 - 5.8% - 3.0%)  [BUYMA手数料 + 決済手数料を逆算]
```

100 円単位切り上げ。

### 3.3 最低利益ライン (出品 GO/NO-GO 判定)

```
最低利益 = max(¥5,000, 売価 × 5%)
```

| 売価帯 | 最低利益 | 利益率換算 |
|---|---|---|
| ¥50,000 | ¥5,000 | 10% |
| ¥100,000 | ¥5,000 | 5% |
| ¥200,000 | ¥10,000 | 5% |
| ¥500,000 | ¥25,000 | 5% |

理由: 
- 低価格帯 ¥5,000 で労働コスト (30-60 分) と平均的トラブル 1 件の送料負担
  をカバー
- 高価格帯 5% で為替変動 ±5% や関税誤差を吸収

## 4. 市場連動価格決定ロジック

### 4.1 市場データ取得 (`fetch_buyma_market_prices.py`)

- 対象: BUYMA 検索結果ページ `https://www.buyma.com/r/{キーワード}/`
- 手段: Playwright (chromium headless) で HTML 取得
- 検索キーワード優先順位:
  1. **ブランド + SKU (型番)**: 同一商品ピンポイント (例: "Gucci 446744 DTDIT")
  2. **ブランド + タイトル抽出** (SKU 検索でサンプル < 3 件の場合): 広め
- 抽出: `class="product_price"` や `Price_Txt` 内の価格。`price_reference`
  (旧価格) / `coupon-price` は除外。¥15,000 未満の値は除外 (送料・Pt 等)
- IQR 外れ値除去後、median / min / max を出力

### 4.2 価格決定 (`app/core/pricing.py` `decide_final_price`)

```
if 市場データなし or サンプル < 3 件:
    → target_price (25% 利益率) を採用
elif 市場 median < 原価 × 50%:
    → 偽相場扱いで無視、target_price を採用
    (ブティック系ブランドの "BUYMA デフォルト表示" 対策)
elif 市場 median × 0.95 < 原価下限 (最低利益 floor を満たす売価):
    → SKIP (below_breakeven): 相場でも赤字
else:
    → min(市場 median × 0.95, target_price × 1.5) を採用
    (中央値 -5% で価格競争力、target × 1.5 を上限ガード)
```

### 4.3 決定値のサンプル (実データ)

| 商品 | 原価 | target (25%) | 市場 median | 最終売価 | 判定 |
|---|---|---|---|---|---|
| BRUNELLO CUCINELLI Shoulder Bag | ¥524k | ¥717k | — | ¥717k | no_market_data |
| PETAR PETROV The Serenade Dress | ¥158k | ¥216k | ¥248k (n=3) | **¥236k** | market_aware |
| GIVENCHY Bootcut Pants | ¥120k | ¥164k | ¥210k (n=3) | **¥199k** | market_aware (上値追い) |
| GIVENCHY Tailored Pants | ¥129k | ¥177k | ¥115k (n=28) | — | **SKIP** (below_breakeven) |
| AFTERCOAT Zipped Cape | ¥154k | ¥212k | ¥44k (n=8, ratio 28%) | ¥212k | 偽相場無視 → target |
| THE LATEST Stretch Pants | ¥24k | ¥33k | ¥30k (n=11) | — | SKIP |

## 6. 実際の月商試算 (複数シナリオ)

### 6.1 前提

- 出品作業: 自動 (1 件あたり手動 30 秒の介入)
- 受注後作業: 買付・検品・再梱包・発送 = 1 件 30-60 分
- 想定成約率 (BUYMA ショッパーの平均): 月次出品 20 件 × 成約率 5-15%

### 6.2 シナリオ別 月商

| 成約率 | 月間成約数 | 平均利益 (¥34k) | 月次利益 (手取り前) |
|---|---|---|---|
| 3% | 0-1 件 | ¥34k | ¥0-34k |
| 5% | 1 件 | ¥34k | ¥34k |
| 10% | 2 件 | ¥34k | ¥68k |
| 15% | 3 件 | ¥34k | ¥102k |

労働時間 (受注後の実作業): 1-3 件 × 30-60 分 = 月 1-3 時間。時給換算 ¥30-50k
（ただし出品作業・返品対応・価格メンテ含まず）。

### 6.3 出品数を増やす場合

baseblu は日次で在庫変動するため、毎日 filter 実行すれば月 100-300 件
出品可能。成約率 5% なら月 5-15 件成約、月次利益 **¥170k-510k** も射程。

## 7. 主要リスクと緩和策

### 7.1 為替変動

- 原価は発注時 (= 顧客入金後) の EUR 相場に依存
- 計算は為替 163 円/EUR 固定
- EUR +5% 変動で売価帯 ¥200k の商品なら原価 +¥10k 増 → 利益喪失
- **緩和**: 最低利益 floor 5% で ±5% 変動を許容。超える場合は出品済み
  商品の価格を毎週再評価 (`update_listed_prices.py`)

### 7.2 在庫切れキャンセル

- BUYMA ではキャンセル率がショッパー評価に直結
- baseblu で売切れた商品を出品し続けるのは致命的
- **緩和**: `check_inventory.py` で日次チェック (6 時間おきを推奨)。
  現状 baseblu の売切検出は自動、BUYMA 側の出品停止は手動推奨
  (Playwright UI 操作のスケルトン実装あり)

### 7.3 競合価格の崩壊

- 特定商品が複数ショッパーで大幅値下げされると追随できず売れない
- **緩和**: 市場連動価格ロジック `decide_final_price` で相場の -5% を
  採用。ただし原価を割る商品は SKIP

### 7.4 返品対応

- BUYMA ショッパー規約上、返品は原則ショッパー負担 (国際送料 ¥3-5k)
- サイズ合わない/イメージ違い等で発生
- **緩和**: 最低利益 floor ¥5,000 はこの 1 件分送料相当。複数返品は
  赤字化するため BUYMA 購入者の信頼スコアでフィルタする運用改善が必要
  (システム化は未実装)

### 7.5 BUYMA 規約違反

- ブランド画像盗用、無在庫転売表記等で出品取下げ・最悪アカウント停止
- タグ誤付与も「適していないタグが付与された商品は出品を取り下げます」
  と規約明記
- **緩和**: タグは `data/tag_reference.json` + `data/tags.json` で
  保守的にルール化 (明確な根拠のある素材・柄タグのみ)

### 7.6 ブティック系ブランドの BUYMA 実在性

- 開発初期に AFTERCOAT / THE LATEST など BUYMA 本体に存在しない
  ブランドが発覚 → `brand_not_found` で出品不可
- **緩和**: CDN API + DOM サジェストのフォールバック実装済。それでも
  出品できないブランドは `brands.json.unregistered` で除外

- [ ] 返品率の追跡ロジック無し

### 8.2 価格ロジックの精度問題

- ブティック系 (流通量少) ブランドで SKU 検索すると BUYMA デフォルト
  リスト (¥25,980 / ¥26,900 / ¥30,000 等の似た値) を拾うため偽相場
- 暫定対策: `市場 median < 原価 × 50%` で無視 (11/15 件の誤 SKIP 救済)
- 残 3 件の低価格帯は境界ケースで対応難

### 8.3 市場サンプルの質

- n=1-2 のサンプルだと中央値信頼性低
- サイズ・色のバリエーションが混在 (例: 同 SKU でも size M と XL で
  価格差あり)
- BUYMA は「偽物疑い」商品も検索結果に混入する可能性

## 9. 収益性の判断軸 (レビュー依頼)

**レビュー AI への質問:**

1. **この業態 (BUYMA ショッパー) 自体の月次純利益期待値** (日本在住個人、
   月 20-100 件出品、成約率 3-10% を前提)
2. **価格計算式の抜け漏れ** (消費税/関税/VAT/送料/手数料の計算順序、
   税率等に誤りはないか)
3. **最低利益 `max(¥5k, 5%)` の妥当性** (自社発送 + 返品負担前提)
4. **市場連動で -5% のポジショニングは強気か弱気か** (BUYMA 競合を
   相対的にどこに置くべきか)
5. **BUYMA シーズン的な売れ筋** (baseblu のイタリアセール時期と日本購入者
   需要のタイミング乖離リスク)
6. **スケールする場合の手間の壁** (月 100 件以上受注したら自社発送は
   物理的にボトルネック)
7. **参入障壁と競合密度** (同様の自動化ツールを使う強豪 vs 個人ショッパー
   が混在する市場で差別化余地)
