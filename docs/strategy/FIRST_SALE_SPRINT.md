# First Sale Sprint — 問題の再定義と最小閉ループ (2026-07-03)

## 1. 問題の再定義

### 従来の問題設定 (暗黙)
「BUYMA 自動出品ツールを完成させる」— 4.5 ヶ月・131 コミット・354 テストを
投じたが、本公開 0 件・売上 0 円。完成度が上がるほど「公開はもう少し完成して
から」の判断が強化される構造だった。

### 再定義した問題
**「本システムは open-loop である」** — pricing / opportunity / demand の全係数が
仮定値のまま、実市場からの帰還信号 (自社出品のアクセス・ほしいもの・成約) を
消費するコードが 1 行も存在しなかった。

- `opportunity.py` は「係数は運用実績で較正する」と自ら書いているが、
  運用実績を取得する経路が未実装だった
- `sales_report.py` は「出品できた」件数しか数えられない
- PROFIT_FIRST_INSTRUCTIONS.md のフェーズ 1 目標「手動出品して最初の 1 件を
  売る」(2026-04) は達成されないまま、ツールの完成が暗黙の前提条件に昇格した

**解くべき問題は「出品の自動化」ではなく「フィードバックループを閉じること」。**
ループが閉じれば、何に投資すべきか (価格 / 画像 / 出品数 / 自動化) はデータが
教えてくれる。閉じなければ、どれだけ作っても仮定の上に仮定を積むだけ。

## 2. 鍵になる観察: 残存ブロッカーは「自動公開」しか阻んでいない

| 未解決課題 | 下書き保存 | 人間による公開 |
|---|---|---|
| 発送地 radio の React state (2026-06-16 修正、未検証) | 阻まない (未設定でも保存可) | 管理画面で人間が設定すればよい |
| カテゴリ第 3 階層の未採取 leaf | ほぼ阻まない (fallback あり) | 公開前に人間が目視確認 |
| publish フロー未検証 | 関係なし | **人間がクリックするので不要** |

∴ **下書き = ツール / 公開 = 人間** の分業なら、今日すでに全経路が開通している。
自動公開の完成はスプリントの前提条件から外れ、「成約が出て量産が正当化された
後の投資」に降格する。副次効果として、未検証コードによる誤公開リスクと
プラットフォーム対策リスク (下記 §5) も下がる。

## 3. 最小閉ループ (実装済み)

```
filter CSV ─→ first_sale_sprint.py ─→ 手順書 MD + マニフェスト
                    │                     (下書き=ツール、公開=人間)
                    ▼
      buyma_auto_listing.py --draft --from N --limit 1
                    │  (公開のたびに --mark-published ROW=ITEM_ID)
                    ▼
      track_listing_funnel.py  … アクセス/ほしいもの/売切を実測 (2-3日おき)
                    │            → data/funnel_history.json
                    ▼
      decision_gate.py  … モデル自身の予測を Poisson 検定し次の一手を機械判定
```

### Mac での週次サイクル (3 コマンド)

```bash
# 週初: スプリント生成 (初回のみ) → 手順書に従い下書き→人間公開→ mark
python3 scripts/first_sale_sprint.py            # → outputs/sprints/*.md
# 2-3 日おき: ファネル実測 (初回は --debug-html でセレクタ確定)
python3 scripts/track_listing_funnel.py
# 週末: 判定
python3 scripts/decision_gate.py
```

## 4. 意思決定ゲート — 事前コミットした判定基準

`opportunity.py` の sale_probability (月次成約確率) は検証可能な予測である:

- λ = Σ p_i × (公開経過日数_i / 30)、H0 の下で成約数 ~ Poisson(λ)
- 成約 0 のまま exp(-λ) < 10% → **モデル棄却** (係数が過大)
- rule of three: 露出 n 商品・月で成約 0 → 95% 信頼で月次成約確率 < 3/n

| 条件 (優先順) | 判定 | 次の一手 |
|---|---|---|
| 成約 ≥ 1 | **SCALE_UP** | 量産解禁 (50-100 件 draft)・在庫 Guard 日次化・係数較正 |
| 公開 <5 件 or <7 日 | COLLECTING | 公開を積む・funnel 採取 |
| 週アクセス中央値 <5 | EXPOSURE_PROBLEM | 価格でなく露出: 出品数増・最安値表示確認・画像比較 |
| exp(-λ) < 10% | CONVERSION_PROBLEM | wish 率で分岐: 価格/信頼 or 画像/品質。係数引き下げ |
| その他 | ON_TRACK_WAITING | 公開数を増やして判定到達を加速 (残日数を表示) |

閾値は `app/core/decision_gate.py` 冒頭に定数として事前コミット済み。
変更するときはコミットメッセージに理由を書くこと (その場の気分による
基準の後退を防ぐため)。

## 5. プラットフォームリスク (2026-07-03 調査)

- BUYMA で最も重大なリスクはアカウント停止。主要因は **総合評価 3.0 未満**、
  偽造品の疑い、不正行為 ([リサーチの達人](https://buyma-essence.com/buyma-account/),
  [規約ルール20選](https://www.buyma-professional.com/actives/actives-4034/))
- **無在庫型の出品自体は規約違反ではない**が、納期遵守・商品情報の正確性が
  条件 ([解説](https://makoto1688.com/blog/buyma-drop-shipping/))。
  → キャンセル (=評価毀損) 防止の check_inventory.py が売上発生後の最優先
- 本スプリントの設計はリスク低減と整合: 公開は人間クリック・公開間隔
  5-15 分・少量から開始・下書き生成のみ自動

## 6. この設計が守る不変条件

1. **すべての公開が計測の分母に入る** (mark-published を挟むため)
2. **判定は事前コミットした基準でのみ行う** (decision_gate.py)
3. **「もう少し完成してから」は SCALE_UP 判定後にのみ許される**
4. 自動公開・画像加工・新仕入先などの投資判断は、ゲートの verdict を
   引用して行う (気分ではなくデータで)
